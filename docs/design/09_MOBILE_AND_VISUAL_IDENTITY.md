## Part A — The mobile experience

### A.1 Orientation
Landscape, exclusively. The cutaway station is a horizontal composition; landscape also matches the two-thumb interaction model. Portrait is permanently cut (03 §6). Safe-area insets (notches, home indicators) respected by keeping all interactive UI inside platform safe zones.

### A.2 Session length
Designed sessions of 5–12 minutes covering one to two day-phases; a typical day with a delegated run fits ~12 minutes, and an active-run day may reach ~16 (session math per 02 §3, D-034). Optional active nightruns are 3–6 minutes and always substitutable by delegation. No content requires a longer continuous sitting; the campaign is completable entirely in 5–8-minute sittings.

### A.3 Safe stopping points
Every phase boundary (4/day) is an autosaving, marked safe stop; every confirmed decision is durable; the nightrun launch is an explicit opt-in gate. The session loop deliberately ends on the exhale (day report / phase preview), so the natural stopping point is also the emotional rest point (Pillar 5).

### A.4 Pause behavior
The base game is pause-native: nothing in Swelter/Slack/Graymorn advances without player confirmation, and in-phase ambient simulation pauses freely. Active nightruns hard-pause on interruption (call, app switch, notification shade) and offer resume-or-delegate on return. There is no scenario in which the OS taking focus costs the player anything.

### A.5 Offline-progress philosophy
**None, in either direction.** No offline decay, no offline yield, no catch-up mechanics, no real-time appointments. Absence is consequence-free by design (Anti-pillar 1; quality gate). The fiction supports it: the stationmaster's log resumes where it left off.

### A.6 Touch interaction philosophy
- **Tap to inspect, tap to commit; drag only for assignment** (survivor → room) **and for footprint positioning inside the build lens** (10 §16) — with a tap-tap alternative for every drag.
- One-thumb operable in base mode; pinch-zoom has a button alternative (07 §17).
- Touch targets ≥ 48 dp/pt for primary controls with ≥ 8 dp spacing (the stricter of the two platforms' minimums, adopted as the single spec); secondary chrome ≥ 28 pt; primary actions live in thumb-reach corners; destructive/irreversible actions always confirm.
- No gesture vocabulary beyond tap / drag / pinch — nothing hidden behind long-press-only or multi-finger input.
- The 30-second loop (02 §2) is the interaction contract: notice → inspect (1 tap) → decide (≤ 4 options) → commit (1 confirming tap) → feedback.
- **Build mode (10 §16):** a toggled lens over the same cutaway, not a separate screen. Tap a bay/section → a verb card (2–4 relevant construction verbs with quoted costs); room placement uses ghost previews with clear valid/invalid states and a confirm step; a full expansion decision (survey → order) commits in ≤ 6 taps. **No drag-drawing of pipes or wires, ever** — utilities are trunk/node works orders. The section survey report is (like the radio scheduler) a named allocation-view exception to one-decision-at-a-time.

### A.7 Notification philosophy
Opt-in only, player-scheduled only ("remind me tomorrow evening"), and never generated by game state — because game state cannot change while away (A.5). No re-engagement, streak, or FOMO notifications, ever. Default is zero notifications. If the player never opts in, the OS permission is never requested; when they first schedule a reminder, the permission ask is framed diegetically at the Listening Post (in line with both platforms' request-in-context guidance), and denial costs nothing.

### A.8 Accessibility commitments (baseline, tested in 07 §19)
Reading surfaces scale to 200%, dense HUD to 130% minimum, body-text contrast ≥ 4.5:1 (D-021); color-safe palette with redundant shape/icon channels (the engineer's overlay is the canonical redundant channel at overview zoom); captions for all audio including alarm identities; fully playable muted, including intermediate warning states; no reflex requirement in base mode and a 1.5 s reaction floor plus full delegation path (with gate calls) for runs; reduced-motion mode (slice scope); left/right-handed layout mirroring in the full game.

### A.9 Information-density limits
- HUD: **5 resource indicators + day/phase clock** (within the ≤ 6 resource-indicator gate) **+ the persistent crew strip** (4 resident portraits, +1 on Juna's arrival, in a thumb-reach corner; paged in the full game — D-034/D-039). Portraits double as need/Stress glance state (canon need names per 17 §1, D-043) and as the tap-tap assignment source; the strip is the guaranteed thumb-legal path to any ledger page (direct sprite-tap is a bonus affordance). Utility states live in the station picture, not the HUD.
- **Enumerated chrome budget (D-039):** the complete persistent-control set is: resource HUD + clock (top edge), crew strip (left thumb corner), build-lens toggle + engineer's-overlay toggle + zoom button (right thumb corner cluster), alert badges (in-world, anchored), confirm/back (context corners). Nothing else is persistent; **full-screen allocation views (radio scheduler, section survey report, load-priority board) suppress the crew strip and resource HUD** — "persistent" means persistent in world/overview contexts.
- Max **3 alert badges** visible simultaneously; the event scheduler queues the rest (and may never exceed 2 active crises). Badge behavior per zoom: ≥ 44 pt anchored to (not inside) rooms at overview; docked to the chalk plate at room zoom.
- Decision cards present **one decision at a time**, with 2–4 options each. **Named allocation-view exceptions (three, closed list):** the radio scheduler (07 §10b), the section survey report (10 §16), and the charge load-priority board (≤ 8 load-class rows; 07 §4 usability criterion) — each a single allocation decision presented whole.
- Any single screen answers one question; anything needing two screens of explanation gets redesigned or cut (readability gate T1).

## Part B — Visual identity (concept level)

Working name for the identity: **"soot and lamplight."** Warmth is earned light inside a cold ruin; the station heals visibly as the player restores it.

### B.1 Camera and composition
Side-cutaway 2.5D, orthographic-leaning with shallow parallax depth (3–4 layers). Two working zooms: **overview** (the slice's three-level section composes on one landscape screen: concourse above, platforms mid, service vaults below) and **room zoom** (one room fills ~60% of frame for scenes and panels). **The station grows (D-038):** blocked sections render in the frame as dark, legible potential — the ruin the player will win back is always visible at the edge of the light. As the full-game station outgrows one screen, overview keeps the "one glance, no screen transitions" principle per the R-16 ladder: section-emphasis scaling first, then gentle edge-pan between named wings — never a menu of disconnected screens. Nightrun locations use the identical camera language — the ruins are a dark mirror of home.

### B.2 Environment treatment
Modular 3D kit rendered stylized (hand-painted texture feel, controlled graphic edges — no photorealism, no outline-cartoon). Every module must testify to *former public transit*: tile bands, enamel signage voids, platform edge stripes, cable trays, the stranded train whose cars are now rooms. Damage reads in the architecture (buckled panels, water stains, soot shadows), not in decals alone.

### B.3 Character proportion
Stylized-realistic at ~1:6.5 head ratio; silhouette-first design with one distinguishing shape + one color key per resident (Imka's high-collar work coat, Ash's sling bag, Teo's runner's wrap, Maren's kiosk apron). Readable at overview distance by silhouette and gait alone. Forbidden: chibi/bobblehead proportions, photoreal likenesses.

### B.4 Lighting language
Lighting *is* the interface of hope: tungsten amber pools where the station lives, teal-slate darkness where it doesn't yet, ember/indigo for the surface at night, bleached ash-white heat-haze for the lethal day. Restoration = light returning, room by room (each restored room permanently warms). Alarms shift light color *locally* at the failing subsystem first — light telegraphs before UI does.

**Channel-separation rule (D-035):** each slow variable owns a distinct visual carrier — **restoration owns color temperature; Accord owns occupancy and lamp count** (residents gathering vs. avoiding common spaces, the proportion of lamps lit within an already-restored room, and the presence of domestic props); alarms own local hue shifts; damage stages own silhouette and material state. Accord never tints ambient light (that earlier idea collided with restoration warmth in the same rooms); Accord-colored *scene lighting* appears only inside the scripted warm/withheld canteen scenes.

**Perf degradation ladder (R-05, pre-approved):** lighting channels degrade in documented order under performance pressure, never ad hoc — alarm = emissive-material swap + sprite glow; restoration warmth = baked lightmap swap per stage; scene lighting = scripted only. The engine perf spike (R-15) tests the full channel set at 30 fps on baseline devices.

### B.5 Material language
Soot, enamel, riveted steel, worn brass, waxed canvas, chalk. Repairs are visible patches: weld seams, stitched canvas, wire splints — the jury-rigged stage must *look* jury-rigged. Water is precious and always rendered carefully (drips, condensation on the cistern). Cinderfall is matte, dry, and hot-edged — never snow-like.

### B.6 Palette logic
| Context | Palette | Meaning |
|---|---|---|
| Lived interior | Tungsten amber, soot umber, teal-slate shadow | Earned warmth |
| Unrestored interior | Teal-slate, cold gray-green | Work remaining |
| Surface day (unseen except through seals/screens) | Bleached ash-white, heat-shimmer orange | Lethality |
| Surface night (runs) | Deep indigo, ember orange accents, lantern pool | Fragile opportunity |
| UI | Bone-white line work on smoked glass panels, chalk accents | Quiet, diegetic-adjacent |
Forbidden pairings: institutional blue-and-yellow as any identity; full charcoal monochrome (04 §5).

### B.7 Interactable readability
One consistent grammar: interactable objects carry a **brass-and-chalk** treatment (worn-bright edges, chalk tally marks by the door of every workable room) plus a soft breathing highlight at inspection range. In runs, the lantern's light radius is the interaction radius — literal illumination as affordance.

**Zoom-dependent exceptions (D-035, replacing the earlier blanket no-floating-icons rule):**
- At **room zoom**, badges live on the room's chalkboard plate and posture/idle telemetry is guaranteed.
- At **overview zoom**, alert and need-state badges render ≥ 44 pt *anchored to* rooms (docking to plates on zoom-in), and the player-toggleable **engineer's overlay** — gauge-glass and chalk-mark diegetic styling — renders subsystem state as shape-coded markers. The overlay is the canonical redundant channel for color-blind and muted play (07 §19) and the first rung of the R-16 readability ladder (default-on if the blockout test demands it). Posture telemetry is *not* promised at overview; chalk-plate badges carry need states there.

### B.8 Damage, repair, and growth progression
Three stages per room/subsystem, silhouette-distinct: **failing** (dark, leaking, hazard-marked), **jury-rigged** (patched materials, flickering half-light, audible strain), **restored** (warm steady light, clean animation loop, resident-added domestic details). Above the per-room stages sit the **four station development stages (10 §13, D-038)** — Refuge → Functioning Shelter → Settlement → Underground Home — carried per-section by lighting warmth, clutter composition, decoration density, and resident behavior, so a growing station wears its history at its frontier. Construction itself is staged and visible (rubble shrinking, waterlines falling, framing rising); residents decorate reclaimed spaces autonomously as Accord and tenure grow. **The screenshot test is a binding acceptance gate (07 §21):** progress must be recognizable from an unlabeled screenshot with the HUD hidden. Domestic detail accruing over time is the visual proof of the whole premise.

### B.9 UI relationship to the world
UI is a thin, quiet layer styled after railway artifacts (punch cards, chalkboards, gauge needles) as *motifs*, rendered flat and modern for readability — diegetic-adjacent, not diegetic-literal. The world carries state (light, posture, drips); the UI carries decisions (cards, ledgers, schedules). When both could show something, the world shows it first and the UI confirms it on inspection.

### B.10 What must not resemble the main inspirations
No vault-door imagery, numbered-vault branding, uniform-suited population, mascot figures, or retrofuture terminal chrome; no charcoal-photocopy monochrome treatment, scrawled-diary UI, or war-reportage framing. The squint test (04 §7 O1): at thumbnail size, Signal 45 must read as *warm light in a train station underground*, not as any existing shelter game. This is an art-stage acceptance gate.

### B.11 Production note (binding)
All of Part B is achieved through the controlled modular pipeline: Higgsfield output is upstream reference only (mood, anchors, keyframes, marketing exploration); every shipped asset is authored/rebuilt in the production pipeline with a provenance record (R-03, R-13) and approved inside the **keystone scene** (R-18) against fixed texture standards. The visual identity must survive blockout: the **readability blockout tier** (03 §3.3 — proxy geometry + final lighting rig + ≤3 identifying props/signage per room + character color keys) is where 07's readability gates run, before any final texture exists. Art pace is measured like content pace: 2 rooms + 1 character at production quality during/after the slice set the go/no-go on the style (R-19), with the fallback ladder descoping rendering technique, never the palette law or lighting language.
